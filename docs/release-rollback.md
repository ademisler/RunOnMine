# Release rollback runbook

Rollback is an explicit incident operation. Preserve the failed artifact, its SHA-256, the source revision, logs, and the operator/timestamp before changing state.

## Application rollback

1. Stop the user/system agent and desktop application.
2. Verify the previous artifact SHA-256 and source revision against release evidence.
3. Do **not** downgrade across an unsupported database schema. Run the previous binary's compatibility check first.
4. Install the previous signed artifact, restart, run `doctor --json`, MCP initialize/list/call, and verify approvals.
5. Record the old/new versions, reason, checksums, state backup, and cleanup evidence.

## Connector binary rollback

Managed connector clients use immutable digest directories and an active manifest. Use the managed rollback command/token generated by the update transaction. The config paths, active manifest and agent restart are one rollback transaction. External binaries are never rewritten; re-pin an independently verified file.

## Database/config rollback

Never replace a live SQLite database while the agent is running. Stop all processes, copy the DB plus WAL/SHM and audit key as one backup set, verify ownership, then restore a trusted set. Future schema versions fail closed. Config/secret prepared journals recover automatically; do not delete a journal unless its generation and backup references have been inspected.

## Privileged helper rollback

Stop and uninstall the helper service, verify the allowlist/policy and service executable identities, install the previous signed helper, restart, and run the real multi-user helper acceptance suite. If cleanup identity is uncertain, leave the service disabled and escalate; do not guess-delete paths or processes.

## Downgrade compatibility policy

RunOnMine supports downgrade only when the target application declares compatibility with the current config, state and OAuth schema versions. Unknown/future schemas, changed credential formats, or irreversible migrations block downgrade. In that case restore a complete pre-upgrade backup or roll forward with a fixed build. Connector clients may roll back independently through the immutable version store when their protocol range remains supported.
